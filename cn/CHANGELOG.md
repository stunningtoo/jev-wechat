# 更新日志

格式：每版按 新增 / 改进 / 修复 / 已知限制 / 下载 归类，人话版，不是提交列表。

## v1.8.5 — 2026-11-14

**改进**

- 诊断面板现在记录每次截图的尺寸和平均亮度。截屏成功却「没认出文字」有两种完全不同的原因——系统给了张全黑的图（受保护窗口），或者图是好的但识别器没读出东西——原来两者在界面上长得一样。现在会直接写出来：
  - `截图 1080x2400 几乎全黑（亮度=0）—— 系统给的是空画面`
  - `截图 1080x2400 亮度=193，开始识别`
- 亮度按 32×48 网格采样，只计算、不写盘、不进日志。

**已知限制**

- 与 v1.8.4 相同。

## v1.8.4 — 2026-11-14

**修复**

- 微信上写着「截屏失败：窗口不可见或受保护」，什么也读不到。真实原因是平台错误码 6（`ERROR_TAKE_SCREENSHOT_INVALID_WINDOW`）：微信在 Android 14+ 上报的那个窗口，系统不肯单独交出来，但同一屏走整屏截图是能拿到的。之前的代码只试窗口截图，拒绝就报错，没有第二条路。
- 现在窗口截图被拒时自动改拍整屏，只有整屏也失败才把错误报出来。拍整屏时坐标以屏幕原点换算，比例 1:1，裁剪不需要额外偏移。
- 错误码文案修正：5 才是「窗口受保护（FLAG_SECURE）」，6 是「窗口不可见或已失效」。上一条把 6 写成了受保护，把排查方向带偏了一整轮。

**已知限制**

- 整屏截图会把状态栏、导航栏一起拍进来。裁剪按标题栏与输入框之间取，这两条边上一般没问题。
- 若微信确实标记了 FLAG_SECURE（码 5），两条路都会被拒，那就真的只剩录屏授权一条路。

## v1.8.3 — 2026-11-14

**修复**

- 微信 8.0.80 上仍然是只有一个圆球、什么都不动。装上 v1.8.2 打开内置诊断，看到的是 `nodes=1 ids=0 texts=0`——微信对非系统无障碍服务返回的根节点**没有任何子节点**，一个节点、没有 id、没有文本、连输入框都摸不到。v1.8.2 里「屏幕下半部有没有输入框」这条判断在空树上永远为否，于是每一屏都被当成「不在聊天窗口」，服务直接沉默。
- 现在树为空时不再去树里找证据，直接交给截屏识别，圆球上会写「微信无障碍树是空的，只能截屏识别」。树里既然什么都没有，就只剩截屏这一条通道。

**改进**

- 会话列表也会被截一次（树空时无法区分列表页和聊天页）。加了道便宜的闸：微信底部「微信 / 通讯录 / 发现 / 我」四个标签同时出现在一屏就判定为列表页，不分析；手动点击时提示「这是会话列表，点进一个聊天再看」。

**已知限制**

- 微信树全空的前提下，识别完全依赖截图质量。输入法弹起、深色模式、动态表情、视频通话浮层都会影响结果。
- 微信是否始终返回空树取决于它检测到什么。若某天它恢复返回正文，会先在诊断面板里看到 `texts>0`，那时可以关掉截屏路线。

## v1.8.2 — 2026-11-14

**修复**

- 微信 8.0.80 上完全没反应：新版把气泡容器的混淆 id `id/bkl` 换掉了，识别按旧的 id 找一个都找不到，整条链路就静默停在「不在聊天窗口」。现在不再依赖任何控件 id，改为按布局读——取标题栏与输入框之间那一条消息带，丢掉时间戳、「发送/返回/表情」这类按钮和头像描述，再按行中心落在屏幕哪一半分左右。
- 微信聊天页读不出标题时，整次读取被丢弃，只剩一个圆球。标题现在只是标签和白名单键，两者都容忍缺失，读到的内容照常往下走。
- OCR 认出内容后默认不自动分析，只有专门靠 OCR 的软件（微信就是）永远停在圆球上，得手动点。截图在决定要不要拍的那一刻就已经花掉，这个开关改成默认开。
- 一屏什么也没认出来时完全无声，和程序坏掉无从区分。现在圆球下方会写「这一屏没认出文字」。
- 「未适配的 App 也走 OCR」这个开关从 v1.4 起就存在于设置存储里，但没有任何代码读它，设置页也没有对应入口——勾不到、也不生效。现在接上了，并补了开关。

**新增**

- 设置 → OCR 段下方加「诊断：最近抓取记录」，弹窗直接显示最近 30 次抓取的结果：树里有多少节点、多少带文本、多少落在消息带内、底部有没有输入框、OCR 认出几条、截图失败的错误码。只有计数和坐标，不含任何聊天内容。没有电脑连 adb 也能判断卡在哪一步。

**已知限制**

- 微信如果连底部输入框都对无障碍服务隐藏，判定仍然会失败——诊断里 `底部输入框=false` 就是这种情况，需要换截图路线。
- 与 v1.8.1 相同：微信左右分边依赖行中心位置，长消息跨过屏幕中线时会判错。

## v1.8.1 — 2026-11-13

**修复**
- 微信 / 抖音 / 多闪里「第一次分析之后就不再更新」。截屏识别原来按「包名 + 标题 + 气泡矩形」判重，可这三个 App 都给不出气泡矩形，判重值整场会话恒定，于是第二次起直接跳过 —— 微信 8.0.52 之后正文又从无障碍树里藏掉了，实际效果是只分析了首屏。现在没有气泡矩形时改用 2.5 秒冷却：同一屏不会重复截，新消息来了就会重新识别。
- 抖音 / 多闪点「填入」只会复制到剪贴板、写不进输入框。补上了 `msg_et` 这条查找路径（和读取用的 suffix 是同一个）。微信没有验证过稳定的输入框 id，所以只在「整棵树只有一个可编辑框」时写入，否则退回剪贴板 —— 免得往搜索框里塞草稿。
- 判断接口返回 200 但没有 `answers` 字段时，以前会当成「全部取默认值」，给出一张看着很笃定的「平静 / 不紧张」卡片。现在直接报错。
- 候选回复走按行切分的兜底路径时，会把行首的数字一起剥掉：「3个月后再说」变成「个月后再说」。现在只剥 `- `、`1. ` 这种带分隔符的列表符号。
- 在「自定义」档里填 `https://api.deepseek.com/v1/chat/completions` 时仍按 Jev 决策协议发请求，必然 400。现在只要地址里有 `/chat/completions` 就走 chat 形状。
- 把设置页展示的完整地址粘回「接口地址」框会拼成 `.../chat/completions/chat/completions`。现在已存在的路径段不再重复追加。
- 悬浮气泡在竖屏拖到靠下位置后转横屏，会整个跑到屏幕外且拖不回来。恢复位置时按当前屏幕夹取。
- 展开卡片后按住标题往下拖，「换一组 / 重试」会被推出屏幕底部。展开高度现在跟着位置重算。
- 风险等级颜色和措辞写死了 0..10 刻度。模型用 0..5 时「偏危险」永不出现，用 0..100 时一律红色。现在按模型自报的满分比例算。
- 每轮分析开始时，状态栏会先闪一秒上一轮的残文（「更新失败」「12s」）。现在立刻刷成本轮时长。
- 截屏识别取不到窗口区域时，仍然拿窗口截图去套整屏的坐标换算，识别框会整体偏移。现在这种情况直接用整屏截图。
- 截屏识别的文字整理（遍历行列、算坐标、排序）跑在主线程，长对话时能感到卡顿。已挪到工作线程。
- 知识库的原子写入少了 `fsync`，断电可能留下 0 字节的 JSON。已补。
- 删除联系人时，如果联系人列表写盘失败，历史文件仍被删掉，下次打开联系人还在但聊天记录全没了。现在写盘失败就不动历史。
- 「存为联系人」的读-改-写原本没有持锁，采集线程和分析线程同时触发会存出两个同名联系人，且写失败也提示成功。
- 滚到旧消息时，历史记录会把「上次写入的那屏」一直留在旧位置，导致该联系人的记录永久停更。现在跳过写入的同时也更新基准屏。
- 全角标题（`Ａｌｉｃｅ`、`（１２）`）和半角标题算成两个不同的联系人。名称归一化现在做 NFKC 折叠，并认全角数字。
- 统计知识库条数时会把每个联系人的全部历史读进内存。改成直接数文件里的条数。
- 从 v1.2 迁移到 v1.3 之后，旧的 `openrouter_key` 没有被删掉，同一把密钥在配置文件里留了两份明文。
- 回复接口的「接口地址」被清空时，请求会发到字面量 `/chat/completions`。现在空值回落到默认地址。
- 无障碍服务被系统重建时，分析线程池没有关闭，会随重建次数累积。现在随服务一起关。

**已知限制**
- 与 v1.8 相同：微信 8.0.52+ 对普通无障碍服务隐藏正文，主要靠 OCR 兜底；本版没有引入任何服务名伪装。
- 微信的左右位置判断依赖 `id/bkl` 是气泡本体而不是整行容器，这一点需要更多机型验证。

## v1.8 — 2026-11-13

**新增**
- 支持微信一对一聊天（`com.tencent.mm`）：消息气泡按 `id/bkl` 定位，左右位置判「我 / 对方」，标题用专门的查找逻辑，避免把群公告或某条消息误认成会话名。
- 支持抖音（`com.ss.android.ugc.aweme`）和多闪（`my.maya.android`）。两者是同一套代码，只有包名不同。抖音会按版本混淆控件 id，所以除了输入框 `msg_et` 全部靠结构判断：消息列表按「在输入框上方 → 条目带发送者头像 → 与输入框共享最深容器」三层选，头像贴哪一边就判哪一边发的。
- 判断接口新增「DeepSeek 官方」预设。DeepSeek 没有 Jev 的决策接口，所以同样 7 道题改成提示词发给 `POST /chat/completions`（走 JSON 模式），回过来的 JSON 再映射回原来的题号，下游（悬浮窗、设置页测试、知识库）全部不用改。
- 视觉接口新增「DeepSeek 官方」预设：`deepseek-flash` 支持标准 `image_url`，可以直接做截图转写。

**改进**
- 回复接口改用统一 JSON 模式：提示词要求模型输出 `{"replies":[...]}` 对象，解析时先试裸数组、再试对象里的数组字段（优先 `replies`，其次任意数组字段），最后才退回按行切分。不实现 `response_format` 的网关会自动降级重发，不影响使用。
- 模型返回空内容时直接报错，不再静默变成三条一模一样的占位回复。

**修复**
- 修了抖音 / 多闪「不同会话给出的回复雷同」：旧逻辑会读到后台残留的「消息」页面（可能是故事栏），每次都拿同一批人当上下文。现在按容器层级挑真正的消息列表。
- 修了抖音 / 多闪消息正文读成空串：两个 App 都把正文放在 `contentDescription` 里、`text` 留空，之前只取 `text`，于是整段对话变成空。现在 text 为空时取 description。
- 修了在微信会话列表页误触发截屏识别：现在只有出现 `id/bkl` 气泡才算进了聊天窗口。

**已知限制**
- 微信 8.0.52 之后对普通无障碍服务隐藏消息正文（气泡节点在、文字没了）。所以在微信里主要靠「截屏识别一次」和自动 OCR 兜底，节点树读到的多半是空快照。本版没有引入任何服务名伪装 —— 无障碍服务从 v1.7 起就固定注册为本项目自己的类名，不为了绕过第三方 App 的节点混淆去改它。
- 抖音 / 多闪的分享视频、图片卡片会把标题或作者名当成正文。

## v1.7 — 2026-10-06

**新增**
- 支持 WhatsApp 一对一聊天（测试中）：读取聊天、判断、候选回复、填入整条链路。只读一对一聊天，群聊不读；WhatsApp 里不截屏，「截屏识别一次」也不可用。读取规则来自 @smgonthebeat（#73），按 WhatsApp 2.26.38.73 的录屏数据验证。
- 分析结果改成一张常驻小卡片：收起时只显示风险等级和对方意图，点标题展开看完整分析和候选回复，再点收起。卡片可以拖到屏幕任意位置，每个 App 分别记住位置。
- 候选回复下方新增「换一组」：判断结果不变，只重新生成一组候选，不会和上一组重复。
- 设置里可以选候选回复条数（1 / 2 / 3 条，默认 3 条）；只要 1 条时不做排序，出得更快。
- 判断接口新增「Vercel」预设。选中后自动填好地址 `https://ai-gateway.vercel.sh/typesafe` 和模型 `typesafe-ai/jev`，密钥用 Vercel AI Gateway 的 key。走的是网关的 TypeSafe 兼容接口 `POST /v1/systemone`，和 TypeSafe 直连同一套请求体与 `noul` 答案，默认仍是 OpenRouter。
- 判断接口新增「OpenCode Zen」预设。选中后自动填好地址 `https://opencode.ai/zen` 和模型 `jev-1.13`，密钥用 [OpenCode Zen](https://opencode.ai/zen) 的 key。走的是 Zen 的 TypeSafe 兼容接口 `POST /v1/systemone`，同样一套请求体与 `noul` 答案；`jev-1.13` 输出免费（输入 $0.042/M，一次判断约 1000 输入 token，约 $0.00004），也可以手动改成限时免费的 `jev-1.13-free`（功能受限）。
- 判断接口新增「Opper」预设。选中后自动填好地址 `https://api.opper.ai/v3/compat` 和模型 `typesafe/jev-latest`，密钥用 [Opper](https://opper.ai) 的 key。走的是 Opper 的 TypeSafe 兼容接口 `POST /v1/systemone`，同样一套请求体与 `noul` 答案，价格与 TypeSafe 相同（输入 $0.042/M，输出免费）。同一个地址也能用开源的 Kev 4B：把模型改成 `opper/kev-4b` 即可。

**改进**
- 只有对方发来新消息才重新分析。上下翻聊天记录不会清空卡片、不会重新分析，也不会弹来弹去；更新时旧结果先留着，标题旁显示已等待的秒数，新结果出来再替换，收起时只闪一下提示。
- 候选回复的语言跟随对方最近一条消息：对方说英文就用英文回复。
- 判断和回复各自最多等 30 秒，超时就停下并给出「重试」，不再一直转圈。
- 无障碍服务的注册名称改为 Jev 自己的名称。
- 截屏识别的图片处理移出主线程，识别时界面不再卡顿（感谢 @ahxoeh，#71）。
- 回复和视觉请求明确关闭流式返回，兼容更多中转网关（感谢 @xuancanhit99，#74）。
- 首页和 README 加了一句使用风险提示：在第三方聊天 App 里使用可能不符合其用户协议，账号有被限制的风险。

**修复**
- 修了候选回复偶尔一直显示「生成中」的问题：回复比判断先回来时，结果会被丢掉。
- 修了 QQ 群聊上下滚动时分析面板卡成空白的问题。
- 悬浮窗自己重绘不再触发重复分析；对方发新消息后候选回复不再一闪就没（感谢 @ahxoeh，#71）。

**已知限制**
- 从 v1.4 或更早版本升级后，需要到系统设置里重新打开一次 Jev 助手的无障碍开关（注册名称变了，原来的授权不再生效）。
- 隐藏界面内容或禁止截屏的 App 不支持。
- 界面目前只有中文，英文界面还在准备中。

## v1.3 — 2026-09-22

**新增**
- 接口全可配：判断 / 回复 / 视觉三路接口的地址、密钥、模型可以分别填，内置 OpenRouter、TypeSafe 直连、DeepSeek 官方、通义兼容四种预设，每一路都能单独点「连通测试」。只有一把密钥也够用：回复、视觉留空会自动继承判断接口的密钥。升级会自动把旧密钥迁移到新配置，不用重填。
- 知识库 + 关联上下文：可以维护本地笔记（打标签、可设「常驻」每次都带上）和联系人档案（姓名、跨 App 别名、关系、备注）；分析时自动把命中的笔记和这个人的历史聊天带给模型，回复会尽量贴合知识库里的信息。历史记录默认关闭，开启后也只存在手机本地，一键可清空。悬浮窗面板会显示「知识库 N 条 · 历史 M 条」，长按气泡可直接把当前会话存为联系人。
- OCR 兜底：遇到无障碍树里读不到正文的界面（比如飞书），会自动截屏并用离线中文识别模型读出文字，不联网、不上传图片。任意其他 App 也能在悬浮窗菜单里手动触发一次「截屏识别」。

**修复**
- 修了几个真机验证中发现的问题：某些界面短暂显示的临时标题（比如连接中提示）会污染会话记录；会话列表页会误触发识别；切换会话后面板偶尔空白；群标题有时抓错；密钥输入框显示不完整；页面在部分机型上跟状态栏重叠。

- 升级到这个版本后，需要把无障碍权限关掉再重新打开一次，新增的截屏能力才会生效。
- 新的截屏识别只能读屏幕上当前可见的部分，长消息看不全的地方读不到，偶尔有错字。
- X（Twitter）目前只验证过中文界面，英文界面和群聊私信还没测过；小米 / HyperOS 后台冻结的老问题仍然存在。
